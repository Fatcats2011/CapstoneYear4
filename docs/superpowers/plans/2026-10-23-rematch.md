# Rematch Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** a Mario Kart-style rematch vote on the results screen. Every player votes REMATCH or BACK TO LOBBY within 15 s, and the players who voted Rematch go straight into a fresh match, with no tutorial.

**Architecture:**
- **The vote rules:** a pure `RematchVote` class decides the outcome.
- **The results screen:** a runtime-built `ResultsVote` component on it collects each player's presses and shows ticks and the countdown.
- **The rematch itself:** it goes through a new `ISceneFlow.Rematch()`. That raises a new `GameManager.OnNewMatch` reset, which the menu path raises too, sets a one-shot "skip the tutorial" flag, and loads the match scene directly.
- **Online:** the host holds the vote. A static `RematchSync` seam (like `TutorialSync`) and an `OnlineRematch` relay (like `OnlineTutorial`) carry votes up, and the host's `RematchBoard` down.

**Tech Stack:** Unity 2022.3.62f3, C#, Netcode for GameObjects 1.15.1, Input System 1.14, TextMesh Pro, NUnit Edit Mode tests (Play Mode only inside the network tests, as the project does).

**Spec:** `docs/superpowers/specs/2026-10-23-rematch-design.md`

## Global Constraints

**What changes, and how files are edited**
- No scene, prefab, `.inputactions` or ProjectSettings edits. The results UI is built by code at runtime, as `ResolutionRow` is.
- New `Assets/` files get a `.meta` from `bash tools/newmeta.sh <file>`.
- CRLF files (e.g. `MenuInteractions.cs`, `SceneManager.cs`, `PlayerInstantiate.cs`) are edited with the Edit tool only.

**Branch and testing**
- Branch `steam-phase1a`. Never check out `main`.
- **Leave every change uncommitted:** the user commits. Each task's last step is "leave uncommitted", not a commit.
- Tests:
  - `bash tools/run-tests.sh <filter>`, **one run at a time**: never start a run while one is going.
  - Results are in `Logs/test-results.xml`.
  - Quick compile check: `python tools/compile-check.py`, which ends with `COMPILES`.

**Rules and copy**
- The rules go in small pure classes with Edit Mode tests, as `JoinRules` and `StealRules` do.
- Countdown: `RematchVote.SECONDS = 15`.
- Player-facing text in Bangers, capitals:
  - `REMATCH`, `BACK TO LOBBY`
  - `WAITING FOR PLAYERS… {n}`
  - kick reason: `Taken out of the rematch.`
- Code comments: match the surrounding files (summary docs on public members, short "why" comments).

## Review Focus

1. **A from the golden scene still held, or mashed, as the choices appear.** No vote counts before the choices are open (`ResultsMenu`'s 2 s `QuitDelay`). Test in Task 6.
2. **Presses after the outcome is decided:** a late A/B, or a vote at 0 s. The outcome is decided once, and later presses do nothing. No double scene load. Tests in Tasks 1 and 6.
3. **The host picks Back to lobby while clients have voted Rematch.** Everyone goes to Dispatch together, with no client stranded. Tests in Tasks 1 and 7.
4. **A seat whose player is gone mid-vote:** a client disconnects, or a couch pad is unplugged. A disconnected seat leaves the vote, so the others don't wait on it. An unplugged couch seat simply times out. Tests in Tasks 1 and 6.
5. **The match after a rematch:**
   - A second results screen gets a fresh vote.
   - A later match started from the menu plays the tutorial again, because the skip flag doesn't stick.

   Tests in Tasks 3 and 6.
